## 3. Рабочий цикл (один этап)

1. **Аудит** (Opus): читает код обеих платформ и бэкенда по теме этапа, записывает точные файлы, строки и ожидаемое поведение.
2. **Задание** (Opus → файл `D:\dev\cache\fix\<буква>-<тема>.prompt`): `rules.txt` + «НЕТ терминала, НЕ запускай субагентов» + точные пути + что НЕ трогать. Одно задание — 1 тема и до ~10 файлов. Задания на одни и те же файлы — строго по очереди.
3. **Правка** (Gemini, в фоне):
   `agy --mode accept-edits --settings D:\dev\cache\fix\settings.json --model gemini-3.8-flash-high --effort high --print-timeout 2300s -p "$(cat prompt)" </dev/null`
4. **Пока Gemini работает** — Opus готовит аудит и задание следующей темы (файлы не должны пересекаться с текущим заданием).
5. **Ревью** (Opus): `git add` предыдущего шага → `git diff` только нового. Проверяет логику, отмену корутин, утечки, паритет с другой платформой, словари (ключи × 3 языка, без дублей). Мелочь правит сам, крупное — повторное задание Gemini.
6. **Проверка**:
   - Android: `assembleDebug` + `testDebugUnitTest`, затем эмулятор `Pixel_8` (скриншоты ключевых экранов).
   - Бэкенд: `go build ./...` + `go test ./internal/middleware/... ./internal/service/...`.
   - iOS: push ветки → GitHub Actions (`ios.yml`), ошибки — в артефакте `ios-test-results`. Ждать в фоне, параллельно делать Android.
7. **Коммит → push → PR** в `main`, статус — в этот файл.
8. **Не ждать.** Пока PR ждёт «да», Opus сразу начинает следующий этап в новой ветке от текущей (PR идут цепочкой). Если этап упёрся в «нужно от Пользователя» — пропустить и взять следующий незаблокированный.

**Останавливаться и спрашивать только здесь:**
- слияние PR в `main`;
- любой push в `main` с изменениями `backend/**` (это деплой на Heroku);
- Heroku, база, Supabase, Firebase, App Store Connect, Google Play;
- продуктовые решения (пометка 🟡 ниже).

Никогда: `--dangerously-skip-permissions`, секреты в git, ввод ключей за Пользователя.
